# Tallymark standing rules
Users: market traders and shop owners (Port Harcourt, Lagos, Aba and similar) on low-end Android phones and slow data.
Simplicity: common actions in 3 taps or fewer; one primary action per screen; at most 5 fields before "More details"; plain words ("Who owes me", "Daily book", "What's left", "Sold on credit"); no jargon, no emojis, no chatty copy; human, specific error messages; every empty state has one clear next action; advanced options sit behind "More"; optional modules stay hidden until enabled.
Perception: reuse the existing design system exactly (one icon set and stroke weight, one radius and shadow system, strict spacing). No AI-looking patterns (gradients, sparkles, generic card grids, stock art, AI branding). Documents must look like a serious company issued them. Correct ₦ and Nigerian formats everywhere.
Security: RLS on every table, deny by default. SECURITY DEFINER functions use a fixed search_path, schema-qualified objects, validated arguments, no dynamic SQL, and EXECUTE revoked from public. Idempotency keys on every document and payment creation. Append-only audit_log. No secrets in client code, logs or URLs. Treat all user text as hostile (escape in UI, PDF, QR, WhatsApp text and CSV). Strict CSP and security headers. Rate limits are stored in Postgres, never in server memory.
Money: integer kobo only; money is recorded only when a payment is recorded; Africa/Lagos for all day boundaries.
Change discipline: additive migrations only, each with a rollback; no change to existing behavior unless specified; every phase ends with regression tests passing and a short report.
